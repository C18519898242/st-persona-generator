# SillyTavern 表情图片包生成器设计

## 目标

为已有角色生成一套可直接上传到 SillyTavern“角色表情”扩展的标准表情图片包。

首个验证角色为“吴莹莹”。脚本读取角色现有的 `profile.json`、头像和全身像，以同一人物、同一发型、同一服装和同一构图生成 SillyTavern 全部 28 个标准表情。

## 范围

新增独立脚本 `generate_expressions.py`，不改变现有 `bootstrap_character.py`、`generate_profiles.py` 和 `generate_with_gemini.py` 的命令行为。

脚本负责：

- 解析角色目录和参考图；
- 生成 28 张标准表情图；
- 校验输出图片；
- 支持跳过已有有效图片和覆盖重做；
- 创建可直接上传的 ZIP 表情包；
- 汇总成功、跳过和失败结果。

脚本不负责：

- 创建或修改 `profile.json`；
- 生成头像、全身像或 HTML；
- 自动抠图或调用额外的第三方去背景服务；
- 将图片直接写入 SillyTavern 用户数据目录。

## 命令接口

基本命令：

```powershell
python generate_expressions.py --character "吴莹莹"
```

默认根目录来自 `.env` 中的 `GEMINI_DEFAULT_ROOT`。同时提供 `--root` 覆盖默认根目录，保持与现有脚本一致。

支持参数：

- `--character`：必填，角色目录名；
- `--root`：可选，覆盖 `GEMINI_DEFAULT_ROOT`；
- `--model`：可选，覆盖现有默认图片模型；
- `--overwrite`：重新生成所有表情；
- `--no-zip`：只生成图片，不创建 ZIP。

## 输入

角色目录必须包含：

```text
<root>\<角色名>\
├── profile.json
├── <角色名>_头像.png
└── <角色名>_全身像.png
```

参考图查找沿用现有兼容规则，优先选择无数字后缀的新命名；如项目已有旧命名兼容函数，则直接复用。

两张参考图职责固定：

- 头像：锁定人物身份、成年年龄感、脸型、五官和发型；
- 全身像：锁定身材比例、服装、配饰和整体造型。

`profile.json` 提供姓名、外观和服装文字信息，用于增强提示词，但图片参考的身份特征优先级更高。

## 输出

图片写入：

```text
<root>\<角色名>\expressions\
```

每张图片必须：

- 使用 SillyTavern 标准英文标签作为文件名；
- 为 PNG 格式；
- 尺寸为 `896 × 1280`；
- 使用透明背景；
- 为统一的上半身半身像；
- 保持相同镜头、人物位置、姿势、服装和光线；
- 只改变目标表情。

标准标签顺序为：

```text
admiration
amusement
anger
annoyance
approval
caring
confusion
curiosity
desire
disappointment
disapproval
disgust
embarrassment
excitement
fear
gratitude
grief
joy
love
nervousness
optimism
pride
realization
relief
remorse
sadness
surprise
neutral
```

完成后在角色目录创建：

```text
<角色名>_expressions.zip
```

ZIP 根目录直接包含 28 张 PNG，不包含额外的顶层文件夹。

## 生成流程

### 1. 解析与校验

脚本解析根目录和角色目录，加载 `profile.json`，定位头像及全身像。任一必需文件缺失时，在调用 API 前终止并给出具体路径。

### 2. 生成中性基准图

`neutral.png` 优先生成。它同时参考头像和全身像，建立后续表情共同使用的画面基准：

- 自然平静表情；
- 正面上半身；
- 头部、双肩和上衣主体完整；
- 透明背景；
- 固定人物大小和画布位置。

如果已存在有效的 `neutral.png` 且未指定 `--overwrite`，直接复用。

### 3. 生成其余表情

其余 27 张同时引用：

1. 原始头像；
2. 原始全身像；
3. `neutral.png`。

提示词明确三张参考图的职责，并要求仅改变目标面部表情。生成按标准标签顺序串行执行，避免并发请求造成限流，也方便显示进度和中断续跑。

每个英文标签配有固定的中文视觉定义。例如 `joy` 为自然开心笑容，`anger` 为明确生气但不过度夸张，`confusion` 为轻微皱眉和困惑目光。定义只描述可见面部特征，不加入剧情、动作或场景。

### 4. 图片规范化与校验

复用现有 Gemini 响应取图、重试和 PNG 规范化能力。

有效输出必须能够被 Pillow 完整读取、格式为 PNG、尺寸恰好为 `896 × 1280`，并具有 alpha 通道。透明背景由生成提示词要求；脚本验证 alpha 通道存在，但不承诺所有背景像素完全透明，也不执行自动抠图。

无效响应或图片按现有重试策略重试。单个表情最终失败后记录错误并继续下一项。

### 5. 打包

只有在 28 张图片全部有效时才创建或替换 ZIP，避免产出看似成功但缺图的表情包。

未全部完成时保留已经生成的有效 PNG，并打印失败清单。用户修复问题后重新运行，脚本自动跳过有效文件并继续缺失项目。

## 复用边界

优先从 `bootstrap_character.py` 复用：

- 环境变量及 Gemini 配置；
- 参考图查找与编码；
- Gemini 图片请求；
- 响应图片提取；
- 重试；
- PNG 规范化和有效性校验。

如果直接导入会把 CLI 或角色 bootstrap 细节带入新脚本，则只复用稳定的纯函数，不进行与本功能无关的重构。

## 错误处理

- 缺少 API Key、根目录、角色目录、profile 或参考图：立即失败，不调用 API；
- `profile.json` 无法解析：立即失败并指出文件；
- 单张 API 请求失败：按现有策略重试，重试耗尽后记录并继续；
- 输出不是有效 PNG、尺寸错误或缺少 alpha 通道：视为该表情失败；
- ZIP 创建失败：保留所有图片，命令返回失败；
- 只要存在失败表情，命令返回非零退出码。

日志不得打印 API Key 或参考图的 base64 数据。

## 测试

新增 `test_generate_expressions.py`，测试不访问真实网络。

覆盖：

- 28 个标签完整、唯一且顺序稳定；
- 根目录、角色目录和参考图解析；
- 缺少输入时在请求前失败；
- `neutral` 提示词包含身份、构图和透明背景约束；
- 其他表情提示词包含三张参考图职责和“只改变表情”约束；
- 已有有效图片默认跳过；
- `--overwrite` 强制重新生成；
- 无效 PNG 不被当作已完成；
- 单张失败不影响后续表情；
- 未完成 28 张时不创建 ZIP；
- 完整成功时 ZIP 根目录恰好包含 28 个标准 PNG；
- CLI 成功与失败退出码。

实现遵循测试先行：每项行为先添加失败测试，再写最小实现使其通过。

## 验收标准

在“吴莹莹”角色目录运行基本命令后：

1. `expressions` 目录包含 28 张命名正确的有效 PNG；
2. 每张尺寸为 `896 × 1280` 且具有 alpha 通道；
3. 所有图片保持同一人物、发型、服装和上半身构图，只改变表情；
4. ZIP 根目录包含相同的 28 张图片，可通过 SillyTavern 的“上传表情图片包（ZIP）”导入；
5. 再次运行时不重复请求已经有效的图片；
6. 自动化测试全部通过。
